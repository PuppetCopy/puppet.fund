# Website (aelea)

Read the root `CLAUDE.md` first; this adds what binds only here. **Load the `aelea-stream` and `aelea-ui` skills before touching stream or component code** — state vs multicast, behavior/tether, `$intermediatePromise`, and the timing gotchas live there.

- **State DOWN, change UP.** The owning component builds shared state once and passes the `IStream` down as a prop; children emit change up through a `behavior`/`tether` that the owner merges back into the source (`reduce(fold, seed, merge(change, …))`). The loop closes through the stream graph.

- **Build shared state inline at its owner — no single-use stream factory, no module singleton.** Construct the pipeline where the change-edge lives, inline in the owning component (`const walletState = op(walletQuery, switchMap(…), reduce(fold, seed, merge(changeAttest, …)), state())`). A `export function xQuery(change)` called from exactly one owner is the thin-util anti-pattern in stream form: the `op`/`switchMap`/`state` WIRING belongs at the owner, so inline it — only genuinely reusable, non-stream LOGIC (pure `fold` reducers, an async `seed`) stays as imported functions. And never a module-level `export const x = op(…, state())` fed by an imperative `pushX()`: that swaps a traceable behavior edge for a hidden global. Re-instantiating shared state per consumer mints N replay caches of one fact.

- **Callback-world modules get the stream injected** (`initWalletLink(pair)`), draining it via `source.run(sink, scheduler)` for the one imperative edge that needs a synchronous peek. A component's render `map` must never write back into a module.

- **Never unfold promises early.** Broader context passes `IStream<Promise<T>>` through untouched; only the call site that renders it unfolds, via `$intermediatePromise`. Collapsing to a resolved value at the owner destroys the pending signal and makes `null` mean "loading", "absent" AND "broken" at once. A shared record that carries a fallible read keeps it as a field-level promise (`{ wallet, root: Promise<T | null> }`) so the failure reaches every consumer instead of dying at the owner.

- **Fail loud needs a receiver.** Not swallowing is only half: an errored stream nobody renders looks IDENTICAL to a swallow (both paint an empty box), so removing a `.catch` fixes nothing on its own. The rejection must land where failure is displayed (`$intermediatePromise` renders `$$fail`/`$errorCard`; `classifyError` already turns a downed service's HTML page into "Service unavailable"). Ask of every fallible read: which component tells the user this broke? If none, the error is a silent default with extra steps. One loud card at the owning display beats five, so peripheral decorations may stay quiet, but never by inventing a value to stay quiet with.

- **Consumers pull from the root context; they never refetch.** A duplicate view request in the network tab is a consumer bypassing the context, and the fix is to hoist the read into the shared owner, never to add a coalescing/in-flight cache. The service worker cache is the ONLY caching layer. Signing paths are the exception in the other direction: they read FRESH at submit, never from an open-time snapshot.
